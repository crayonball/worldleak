# WorldLeak and WorldRepair

Code for *What Does It Mean to Unlearn? Indistinguishability and Admissibility*. Results are reported in the paper.

## Setup

Python 3.13 and a CUDA GPU.

```bash
pip install -r requirements.txt
pytest -q tests
```

Models and public datasets are fetched from their official hubs at first use, and a local path works wherever a model
is expected. Llama-family models and the WMDP Bio forget corpus are gated: request access from their owners.
Outputs go to `runs/` (set `UNL_RUNS` to change it).

## Layout

| Path | Content |
|---|---|
| `unlearn/worldleak.py` | Admissible region, WorldLeak, projection, certificates. |
| `unlearn/audit.py` | Response labeling, candidate selection by string match, behavior distribution. |
| `unlearn/worldrepair.py` | WorldRepair: sample, label, project, then update under the retain KL constraint. |
| `unlearn/data.py`, `unlearn/models.py` | Dataset loaders, query schema, generation, likelihoods. |
| `configs/` | Settings per benchmark. |
| `scripts/` | Entry points listed below. |
| `tests/` | Unit tests for the math, configs, and inputs. |

## Inputs

`inputs/` is not tracked. Build the author-constructed inputs first:

```bash
python scripts/build_inputs.py tofu-candidates tofu-paired wmdp-paired
python scripts/build_inputs.py muse-indirect muse-retain-qa wmdp-indirect   # needs a GPU
```

The GPU targets are generated by Qwen2.5-14B-Instruct with greedy decoding. WMDP-derived inputs are not distributed
because they pair prompts with protected answers.

## WorldRepair and final audit

```bash
python scripts/repair.py --config configs/tofu.yaml --run-id tofu --set seed=0
python scripts/audit.py --config configs/tofu.yaml --model runs/tofu/repair/model --run-id tofu --tag worldrepair
```

For the other benchmarks use `configs/muse.yaml`, `configs/wmdp_bio.yaml`, `configs/wmdp_cyber.yaml`, or
`configs/wmdp_joint.yaml`. Dotted overrides change any setting, e.g. `--set erase.type=hinge align.type=none`.

## Baselines

Baselines run through OpenUnlearning at a pinned commit:

```bash
python scripts/openunlearning.py setup
python scripts/openunlearning.py train --bench tofu --trainer NPO --run-id <id>
python scripts/openunlearning.py eval --bench tofu --model <ckpt> --run-id <id> --tag npo
```

Trainers: GradDiff, NPO, SimNPO, RMU, MEGD, IDKAP. Audit any resulting checkpoint with `scripts/audit.py`.

## Paired worlds

```bash
python scripts/build_world.py --config configs/tofu_paired.yaml --world A --run-id <worlds-a>
python scripts/repair.py --config configs/tofu_paired.yaml --run-id <repair-a> --set model.name=<world ckpt> paired.world=A
python scripts/paired_worlds.py --config configs/tofu_paired.yaml --world-a <repair-a ckpt> --world-b <repair-b ckpt> \
    --input-a <world-a ckpt> --input-b <world-b ckpt> --run-id <id> --tag worldrepair
```

Repeat the first two steps for world B. `scripts/certificate.py` computes finite-sample certificates,
`scripts/open_ended.py` produces open-ended responses, and `scripts/candidate_diag.py` gives WMDP candidate diagnostics.

## RWKU

```bash
python scripts/rwku_run.py --run-id <id> --persons 0 1 2 3
python scripts/rwku_run.py --run-id <id> --persons 0 1 2 3 --methods rt purge   # a subset of methods
```

This runs Base, in-context unlearning, NPO, rejection tuning (RT), PURGE (released checkpoints, evaluated only), and
WorldRepair per target person, with the RWKU evaluation and the audit. NPO and RT are ported from RWKU's training scripts.

## Leak@k

```bash
python scripts/leak_at_k.py --model <ckpt> --run-id <id> --tag worldrepair --set forget
```

This follows the evaluation of Reisizadeh et al. (arXiv 2511.04934) using the entailment score, for k = 1, 2, 4, 8.
